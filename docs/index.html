> How the YouTube tracker works

Every week, it finds new YouTube videos from the channels Indigitous follows and sends them to MissionEngine. To follow a new channel, add its link to Airtable. The tracker handles the rest.

What happens on each run

One command, python yt_tracker.py, does all five steps in order. Task Scheduler runs it once a week.

  1. 1

    Airtable

    Reads YouTube links from the Content Sources table in the Indigitous - People base.

    URL field
  2. 2

    Google Sheet

    Adds any link that isn't in the Sheet yet as a new row. Existing rows are never changed.

    channel_url column
  3. 3

    YouTube

    Checks every channel in the Sheet for videos posted since the last run.

    YouTube Data API
  4. 4

    Saved locally

    Adds the new videos to a CSV file, so there's always a record on disk.

    new_videos.csv
  5. 5

    MissionEngine

    Uploads each new video. The API skips any video it already has.

    POST /events

Only the Google Sheet gets scraped. Airtable just adds new links to it. If the Airtable step fails, the error is logged and steps 3 to 5 still run.

Follow a new channel

Paste its YouTube link into the URL field of a new row in Content Sources. That's all. On the next run, the tracker copies it to the Sheet and scrapes it. You can also add a row to the Sheet directly.

  • Channel/@handle, /channel/…, /user/…, /c/… or youtube.com/name. Gets every new upload from that channel.
  • Playlist/playlist?list=…. Gets new videos in that playlist only.
  • Single videowatch?v=…, youtu.be/…, /shorts/…. Sends that one video once.

The first time a channel is scraped, how far back it looks depends on new_channel_lookback_days in config.json. Set to "all", it gets the channel's whole history, so the first run can take hours.

OnceSet up a computer

  1. Get the code

    git clone https://github.com/Indigitous/missionengine-tools-youtube
cd missionengine-tools-youtube
pip install -r requirements.txt

  2. Set the four keys

    Set them with setx (see the table below), then open a new terminal.

  3. Add the Google key file

    Put service_account.json next to the script. Share the Google Sheet with the client_email inside it as Editor, so new rows can be added.

  4. Make your config

    Copy config.example.json to config.json. Fill in sheet_id, the airtable block, and the upload block with "enabled": true.

  5. Test without sending anything

    python yt_tracker.py --check-upload
python yt_tracker.py --copy-to-sheet --dry-run

The keys it needs

Keys are stored as environment variables, never in a file, so they can't end up on GitHub by accident.

Daily useCommands

python yt_tracker.py

The full run. All five steps: Airtable, Sheet, YouTube, CSV, MissionEngine.

python yt_tracker.py --check-airtable

Lists the YouTube links in Airtable. Changes nothing.

python yt_tracker.py --copy-to-sheet --dry-run

Shows which links would be added to the Sheet. Drop --dry-run to add them, without scraping.

python yt_tracker.py --check-upload

Tests the MissionEngine login. Sends nothing.

python yt_tracker.py --check-resources

Looks for your 10 most recent videos in MissionEngine, to confirm they arrived.

python upload_csv.py --dry-run

Counts what's in new_videos.csv. Drop --dry-run to resend all of it without scraping. Duplicates are skipped.

WeeklySchedule it

Create a Windows task that runs the full run every Monday at 9:00. Change both paths to match your computer.

schtasks /Create /TN "YouTubeTracker" /SC WEEKLY /D MON /ST 09:00 /TR "\"C:\Path\to\python.exe\" \"C:\Path\to\yt_tracker.py\""

Then open Task Scheduler and turn on "Run task as soon as possible after a scheduled start is missed", so a computer that was asleep catches up.

A Last Run Result of 0x1 means something failed, usually the upload. Open yt_tracker.log to see why. Failed uploads are retried automatically on the next run.

Files next to the script

yt_tracker.log

What happened on every run. Look here first.

new_videos.csv

Every video found, newest at the bottom.

state.json

When each channel was last checked. Delete a channel's entry to fetch it again from the start.

pending_upload.json

Videos that didn't upload yet. They're sent first next run.

rejected_uploads.json

Videos MissionEngine refused, with the reason.

channel_cache.json

Channel lookups, saved to use less YouTube quota.

Secretconfig.json

Your settings. Never commit it.

Secretservice_account.json

The Google key. Never commit or share it.

config.example.json

The template to copy. Safe to commit.

When something goes wrong

Could not resolve channel: <link>

YouTube couldn't find that link. Open it in a browser and fix it in Airtable or the Sheet. It's retried every run.

Google Sheets refused the write (HTTP 403)

The service account can only view the Sheet. Share the Sheet with it as Editor. Scraping still runs.

Airtable returned HTTP 401 / 403

The token is wrong or can't see the base. Check AIRTABLE_TOKEN and its access to Indigitous - People.

upload FAILED (queued for retry)

MissionEngine couldn't be reached. Nothing to do. The videos wait in pending_upload.json and go next run.

… environment variable … not set / must be set

A key is missing. Run setx again and open a new terminal. A scheduled task may only see a new key after you sign out and back in.

quotaExceeded

YouTube's daily limit (10,000 units) was used up, usually by a big first run. Wait a day. Channels that didn't finish are tried again on the next run.
